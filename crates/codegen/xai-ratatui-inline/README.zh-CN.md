# ratatui-inline

用于构建带内联视口的终端应用的 Rust 库——动态 UI 元素固定在终端底部，同时保留上方的滚屏历史。非常适合聊天式界面、命令提示符和交互式终端工具。

## 这是什么？

此 crate 提供创建以下终端应用所需的工具：
- 视口（UI 元素）固定在终端底部
- 视口上方的内容成为终端原生滚屏历史的一部分
- 用户可以使用终端内置的滚动功能浏览历史
- 长行自然换行而不会被截断
- 在历史不断累积到上方时，视口仍保持可见且可交互

典型应用包括：
- 底部带输入框的聊天界面
- 带命令历史的交互式 REPL
- 底部带控制项的日志查看器
- 任何需要保留输出历史的 TUI

## 主要特性

- **内联视口**——UI 保持在底部，内容向上流入滚屏历史
- **自然文本流**——正常打印内容，利用终端的原生行为
- **零拷贝文本处理**——无需分配即可进行高效、了解 ANSI 的文本分段
- **正确换行**——结合 ANSI 序列，正确处理终端宽度边界
- **Unicode 支持**——正确处理 emoji、CJK 字符和组合字符
- **终端调整大小处理**——使用 RIS（Reset to Initial State）提供稳健的调整大小支持
- **同步输出**——使用 DCS 协议实现无闪烁渲染
- **跨平台**——可用于所有终端和多路复用器（tmux、screen 等）

## 架构

### 文本处理

该库采用零拷贝方式进行了解 ANSI 的文本分段：
- **anstyle-parse**——了解 ANSI/SGR 的分段，用于零拷贝逐行拆分
- **零分配**——返回字符串切片，不复制也不分配
- **单遍解析**——只处理一次输入，同时正确跟踪转义序列
- **Unicode 支持**——正确计算 emoji、CJK 和组合字符的宽度

### 滚屏实现

该库采用“自然流”方式实现滚屏：
1. 将光标放到视口顶部
2. 打印内容，让终端自然处理换行
3. 添加视口高度数量的换行符以预留空间
4. 清除并渲染视口

这一单一实现无需特殊模式或变通措施，就能在所有终端和多路复用器上通用。

### 行尾处理

- **LF (`\n`)**——标准行尾，移动到下一行
- **CRLF (`\r\n`)**——Windows 风格行尾，视为单个换行
- **CR (`\r`)**——仅回车，将光标重置到行首（覆盖原内容）

## 设计决策

### 为什么 fork ratatui 的 Terminal？

标准 ratatui Terminal API 没有暴露内联视口操作所需的内部能力：
- **视口区域访问**——需要知道当前位置和尺寸
- **直接定位视口**——必须能够设置视口位置
- **缓冲区管理**——需要重置 back buffer 并访问之前的缓冲区
- **调整大小计算**——调整大小时需要访问缓冲区状态

我们 fork 的 Terminal 提供了这些能力，同时保持与 ratatui API 的兼容性。

### 同步输出

使用 DCS 同步输出协议实现无闪烁渲染：
- begin/end 标记之间的所有操作都是原子的
- 终端每个批次只更新一次显示
- 消除部分渲染状态

## 性能

- **彩色 JSON**：每次操作约 186μs
- **纯文本**：每次操作约 75μs
- 热路径中**零分配**
- 所有文本处理均采用**单遍解析**

### 终端调整大小策略

#### 问题

在主屏幕（而非 alternate screen）上使用内联视口时，终端调整大小会造成问题：
- 终端会在应用收到 SIGWINCH **之前**自动重排内容
- 旧视口边框会被重排成垃圾文本
- 内置的 `autoresize()` 会损坏滚屏历史
- 快速调整大小期间，光标位置查询（DSR）存在竞态
- 不同终端对重排的处理不可预测

#### 解决方案：RIS (Reset to Initial State)

我们采用“核选项”——完全重置并重新渲染：
1. 发送 RIS (`ESC c`) 清除全部内容
2. 重新输出完整的滚屏历史
3. 根据内容量定位视口

这种方式：
- 在所有终端上**一致工作**
- 通过重新输出历史**保留滚屏内容**
- **避免**不可预测重排造成的伪影
- 不依赖光标查询，**没有竞态**
- **处理所有调整大小类型**（水平和垂直）

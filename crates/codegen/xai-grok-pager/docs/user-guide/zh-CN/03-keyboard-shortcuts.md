# 键盘快捷键

本页参考 Grok Build TUI 中的按键绑定。绑定内置，目前无法重新映射。

---

## 输入模式

Grok 有两种输入模式，用于控制你在回滚区中的导航方式：

- **简单模式**（默认）：使用方向键导航，使用 `Shift+Arrow` 在轮次间导航，按 `Space` 聚焦提示框，按任意字母键会自动聚焦提示框。
- **Vim 模式**（选择启用）：使用 `j`/`k` 导航，`H`/`L` 在轮次间导航，`J`/`K` 在回复间导航，`h`/`l` 折叠，`e`/`E` 展开/折叠，使用 `i`/`Tab`/`Space` 聚焦提示框。

默认启用简单模式。要切换到 Vim 模式，请在 `~/.grok/config.toml` 的 `[ui]` 下设置 `vim_mode = true`，或在运行时使用 `/vim-mode` 切换。详情参见[配置](05-configuration.md)。

> **更新提示上下文：** 仅当欢迎页已经显示“有新版本”提示时，`Ctrl+U` 会优先执行
> `QuitForUpdate`：退出当前旧版本并授权本次 ZIP 下载与安装；如果已显式开启自动更新，
> 则等待可能已经开始的后台下载。重新运行 `grok-zh` 即进入新版本。
> 在回滚区、提示框和 Dashboard 等其他上下文中，`Ctrl+U` 仍保留各自原有含义。

下表记录两种模式的绑定。“按键”列显示 Vim 模式绑定，“替代按键”列显示简单模式中的等效按键（方向键等）。

> **需要 Vim 模式**：**回滚区**上下文中的单字母和 `Shift+letter` 绑定（`j/k`、`h/l`、`g/G`、`L/H`、`y/Y`、`o/O`、`r`、
> `x`、`e/E` 以及插入模式的 `i` 替代键）要求在 `~/.grok/config.toml` 中设置 `[ui].vim_mode = true`
> （或使用 `/vim-mode` 切换）。方向键、`Tab`、
> `Esc`、`Space`、`PageUp/Down` 以及所有 `Ctrl+letter` 快捷键在两种模式下都有效。

| `g` | | 跳到回滚区顶部 |

## 焦点

在提示输入框和回滚面板之间切换。

| 按键 | 替代按键 | 上下文 | 操作 |
|-----|---------|---------|--------|
| `Tab` | `Space`（Vim 模式下还有 `i`） | 聚焦回滚区 | 聚焦提示输入框 |
| `Tab` | | 聚焦提示框 | 聚焦回滚区（简单和 Vim 回滚模式均适用） |
| `Tab` | `Shift+Tab`（向后） | 聚焦阻塞卡片（问题、权限提示、取消轮次面板） | 在卡片行之间循环，首尾相接。焦点留在卡片中 |
| `Tab` | `Space`（Vim 模式下还有 `i`） | 聚焦回滚区且有停靠卡片 | 将键盘交还给卡片（栏中的焦点提示会显示卡片名称） |
| `Enter` | | 聚焦提示框 | 发送当前提示 |

**Esc 不是焦点按键。** 它遵循下面的取消/清除/回退语义。轮次进行中的取消是唯一受 `[ui].vim_mode`（回滚导航）控制的分支；没有任何行为依赖 `[ui].simple_mode`（提示编辑器）。覆盖层、模态框、斜杠/文件下拉菜单、语音、搜索和选择会优先接管 Esc。

## 阻塞卡片

有三个界面会等待你回答并在打开期间接管键盘：**问题卡片**（`ask_user_question`）、**权限提示**和**取消轮次面板**。同时打开多个界面时，键盘优先交给权限提示，其次是取消轮次面板，最后是问题卡片；快捷键栏始终显示当前接收按键的界面。

它们共享以下契约：

- `Tab` / `Shift+Tab` 在卡片行之间移动，并在两端循环。它们不会将焦点移出卡片，因此光标始终位于可见位置。
- `Esc` 会逐级退出，一次退一层：先清除卡片中待处理的内容，只有没有可清除内容后才会离开。离开后的去向因卡片而异——问题卡片和权限提示会将键盘停靠在回滚区，供你向上滚动查看背后的上下文（卡片仍在屏幕上）；取消轮次面板的“保持全部运行”则会直接解决面板。
- 键盘停靠后，快捷键栏显示回滚区自身的按键，焦点提示会命名卡片而不是提示框：`Tab/Space: question`。该提示固定显示，因此窄栏不会裁掉唯一的返回路径。
- 在 dashboard 的会话覆盖层中还有一级：键盘停靠后，再按一次 `Esc` 会返回 dashboard，同时保留待处理的卡片。（`Ctrl+\` 在任何状态下都仍会离开。）

### 问题卡片（`ask_user_question`）

| 按键 | 操作 |
|-----|--------|
| `↑` / `↓`、`j` / `k` | 在答案之间移动（在两端钳制） |
| `Tab` / `Shift+Tab` | 循环浏览该问题的答案——从最后一个答案回到第一个。不会进入其他问题 |
| `←` / `→`、`h` / `l`、`[` / `]` | 上一个 / 下一个问题 |
| `1`–`9`、`a`–`f` | 直接选择该答案 |
| `z` | 跳到自由文本行并开始输入 |
| `Space` | 切换聚焦的答案（多选），或在自由文本行开始输入 |
| `Enter` | 选择并前进；在最后一个问题上提交；或编辑自由文本行 |
| `Esc` | 取消选择当前问题的答案；未选择时将焦点停靠在回滚区（按 `Tab` 返回）。但在 dashboard 会话覆盖层内的*第一个*问题上，它会返回 dashboard——在后续问题中，`←` 仍是返回方式，因此先停靠，下一次 `Esc` 才会离开。快捷键栏会显示当前生效的层级 |
| `y` | 复制聚焦的答案 |
| `Shift+X` | 关闭问题（智能体在没有答案的情况下继续） |
| `Ctrl+F` | 将卡片全屏显示 |

无参数的 `/feedback` 面板是此表唯一的例外：它没有可浏览的答案，`Enter` 发送报告，`Esc` 关闭面板。

输入自由文本答案时，`Enter` 提交，`Esc` 返回答案行；其他所有按键都输入到文本字段。

### 权限提示

| 按键 | 操作 |
|-----|--------|
| `↑` / `↓`、`j` / `k` | 在选项之间移动（在两端钳制） |
| `Tab` / `Shift+Tab` | 循环浏览选项 |
| `1`–`9` | 直接选择该选项 |
| `Enter` | 选择聚焦的选项 |
| `←` / `→` | 扩大 / 缩小“始终”回答会记住的范围 |
| `e` | 手动编辑始终允许模式的匹配模式（bash 提示） |
| `Ctrl+F` | 展开 / 折叠完整参数 |
| `Ctrl+O` | 开启始终批准模式 |
| `Esc` | 将焦点停靠在回滚区（按 `Tab` 返回）。不会回答或关闭请求 |
| `Ctrl+C` | 取消请求 |

在“No”行输入会改为向智能体发送消息；按 `Enter` 发送，按 `Esc` 返回选项。

### 取消轮次面板

| 按键 | 操作 |
|-----|--------|
| `↑` / `↓`、`j` / `k`、`Tab` / `Shift+Tab` | 在选项之间移动 |
| `1`–`4`、`Enter` | 确认该选项 |
| `Esc` | 保持全部运行。面板会因此解决，既不会形成死路，也不需要停靠 |

## Esc 键

| 状态 | 手势 | 效果 |
|--------|---------|--------|
| 轮次运行中，**精简模式或关闭 Vim 回滚模式（默认）** | `Esc` | 立即取消（无论提示框还是回滚区聚焦，即使有草稿——草稿会**保留**，不同于 Ctrl+C 的先清除手势）。 |
| 轮次运行中，**全屏 Vim 模式** | `Esc` | 被吞掉，空操作（**不会**取消）。请使用 `Ctrl+C`（或命令面板/其他取消入口）。 |
| 轮次取消中 | `Esc` | 在**所有**模式下重新发送取消（如果第一次确认丢失则重试）。此状态下 `Ctrl+C` 会升级为退出。 |
| 空闲 + 非空提示（文本或图像芯片），**提示框聚焦** | **在 800ms 内按 `Esc` 两次** | 清除提示；非空文本会保存到提示历史。第一次按下会显示“再按一次即可清除”。 |
| 空闲 + 空提示 + 有会话消息，**提示框或回滚区聚焦** | **在 800ms 内按 `Esc` 两次** | 打开回退选择器（等同于 `/rewind`）。第一次按下不会显示提示。 |
| 空闲 + 空提示且没有消息，**或回滚区聚焦且有草稿 / 模式化（`!` `#`）编写器 / 等待输入的待处理覆盖层 / 打开的历史搜索** | `Esc` | 被吞掉，空操作（不会聚焦回滚区）。清除只作用于提示面板；回退要求空的普通模式编写器、没有待处理覆盖层且没有打开历史搜索。阅读回滚区不会改变草稿、编写器模式、等待回答的问题或进行中的搜索。 |

**取消后的缓冲期：** 在由 Esc 触发取消后约一秒内，空闲回退触发仍被抑制——连续按 Esc 停止轮次不会无意间打开回退选择器。只会抑制回退触发；其他 Esc 行为不受影响。

**抢占 Esc（在轮次中途取消/吞掉以及清除/回退前执行）：** 覆盖层、模态框、斜杠/文件/补全下拉菜单、历史搜索、回滚搜索、文本选择、链接高亮、语音，以及**Bash / Remember 模式退出**（提示框为空时按 Esc 离开 `!` / `#` 模式并返回普通提示，即使轮次仍在运行）。无参数的 `/feedback` 会打开报告面板；按 Esc 关闭该面板。

**Ctrl+C 与 Esc：** 轮次运行时有非空草稿，Ctrl+C 会清除草稿并保持轮次；再次在空提示框按 Ctrl+C 才会取消。Esc 会立即取消并保留草稿（全屏 Vim 模式下不会取消——仅在已取消时重试）。空闲时非空 Ctrl+C 一次即可清除；Esc 需要在 800ms 内按两次。

| `Ctrl+L` | 智能体界面 | 打开扩展模态框（**仅限非 VS Code 系列**；在 VS Code / Cursor / Windsurf / Zed 中，`Ctrl+L` 是轮次中途的**插话**，扩展通过 `/plugins` / `/hooks` 打开） |

**注意：** `Ctrl+M` 取决于上下文。提示框聚焦时，它切换多行输入模式；否则打开模型选择器。

**注意：** 精简模式的外部编辑会依次解析 `$VISUAL`、`$EDITOR` 和 `vi`。值可以包含带引号的参数。保存只会替换草稿；空文件会清除草稿。包含粘贴内容、文件或图像芯片的草稿必须在编写器中编辑，否则附件会被扁平化。

**注意：** `Ctrl+'` 是 `Ctrl+;` 在 Windows 上的替代键——某些 Windows 控制台会丢弃标点键上的 `Ctrl` 修饰键。

**注意：** `Ctrl+.` 需要 Kitty 键盘协议（或使用 tmux `extended-keys on` 让协议通过）。在 VS Code / Cursor / Windsurf / Zed 集成终端、VTE、Apple Terminal、Windows Terminal、JetBrains、`extended-keys off` 的 tmux、screen 及其他无 KKP 的环境中，Grok 会将 **`Ctrl+X`** 宣传为主要的快捷键速查键。即使 `Ctrl+.` 不可用，**`Ctrl+X` 始终作为传统控制字符有效**。如果修改后的按键在 tmux 中行为异常，请运行 `/doctor`。

## 图像粘贴与拖放

| 操作 | macOS | Linux | Windows |
|---|---|---|---|
| 将文件管理器中的图像拖入提示框 | Finder ✓ | Files / Dolphin ✓ | Explorer ✓ |
| 在文件管理器中复制文件，然后粘贴 | `Cmd+V` | `Ctrl+V` | `Ctrl+V` |
| 截图或在剪贴板中“复制图像”，然后粘贴 | `Cmd+V` | `Ctrl+V` | **`Alt+V`** |

非图像文件会作为文本插入其绝对路径，而不是芯片。

> **Windows 上的 `Alt+V`** 是 grok 专属功能。Windows Terminal 的默认 `Ctrl+V` 只粘贴纯文本，并会静默丢弃图像剪贴板；`Alt+V` 可绕过拦截器。要让 `Ctrl+V` 也能粘贴图像，请将 `{ "command": null, "keys": "ctrl+v" }` 添加到 Windows Terminal `settings.json` 的 `actions` 中。

### Linux PRIMARY 和 CLIPBOARD

Linux X11 有两个独立的文本选择：

- `Ctrl+V` 读取 **CLIPBOARD**，即显式复制/剪切的选择。它不会回退到 PRIMARY。要使用 `xclip` 将文本放入其中，请执行 `printf %s "text" | xclip -selection clipboard`。
- Grok 中未修改的中键点击会读取 **PRIMARY**（当前鼠标选择），但仅当 `DISPLAY` 非空时才会这样做。纯 X11 可使用原生读取器回退；XWayland 需要 `PATH` 中有 `xclip` 或 `xsel`，这样 Grok 才会读取 X11 选择而非 Wayland PRIMARY。按下时只处理一次，松开不会再次粘贴。
- `Shift+Insert` 是终端原生粘贴所选文本的方式。许多终端也使用 `Shift+middle click` 绕过应用鼠标报告。

通过 SSH 时，远程 Grok 进程通常无法访问终端本地的 X11 选择。请使用终端原生的 `Shift+Insert` 或 `Shift+middle click`，让本地终端通过 PTY 发送所选文本。

## 活动轮次期间（智能体运行中）

智能体生成内容时：

- **普通 `Enter`**（编写器中有文本时）会将后续提示**排队**，稍后发送。当前轮次结束后会运行排队的后续提示——智能体被后台任务或子智能体阻塞等待时，它们会有意**保持等待**（提示会解释等待原因以及如何立即发送）。
- **在已清空的编写器中再次按 `Enter`**（双击 Enter）会立即发送排队队列的**首条**后续提示。
- **立即发送**组合键是**取消并发送**：它会停止当前轮次（后台任务、子智能体和队列的其余内容继续运行），并将你的消息作为下一轮发送，因此消息总是出现在记录底部：
  - **非空编写器** → 立即取消并发送文本。
  - **空编写器** + 有排队后续提示 → 立即发送队列的**首条**后续提示（无需聚焦队列面板）。在队列面板中，相同组合键（或 **[立即发送]** 按钮）会发送**选中**的行。
  - **空闲**，或**空编写器且没有排队内容** → 该按键无操作。
- 智能体**阻塞等待**（等待任务输出或子智能体）时，带文本的普通 `Enter` 也会立即传递——Shell 会取消阻塞中的轮次，并在下一轮运行你的消息。

| 终端 | 主按键 | 替代键 | 操作 |
|----------|---------|------------|--------|
| 默认 | `Ctrl+Enter` | `Ctrl+I` | 立即发送（取消当前轮次，下一步运行你的消息） |
| Apple Terminal | `Ctrl+O` | `Ctrl+Enter`、`Ctrl+I` | 立即发送 |
| VS Code 系列（VS Code、Cursor、Windsurf、Zed） | **`Ctrl+L`** | *（无）* | 立即发送（不使用 `Ctrl+I`——Tab / 主机聊天；通过 `/plugins` 使用插件） |

在 `/multiline` 模式中，`Shift+Enter`（或 `Alt+Enter`）会发送，而普通 `Enter` 插入换行——但轮次中途**空**编写器有排队后续提示时，普通 `Enter` 仍会立即发送首行（与普通模式相同）。（在非 VS Code 系列且已绑定的情况下，`Ctrl+Enter` 是轮次中途的立即发送；不会提交新的空闲轮次。）

立即发送是有意打断的操作——其含义是“停止当前操作并处理这个”。若想在不停止智能体的情况下传递备注，请使用普通 `Enter` 排队；智能体会在下一轮边界接收它。

> **WezTerm**：这些修改过的 Enter 按键需要在 WezTerm 配置中设置 `enable_kitty_keyboard = true`。完整步骤和一行式解决办法见[终端支持指南](21-terminal-support.md#problem-ctrlenter-doesnt-interject-in-wezterm)。

> **Windows（非 VS Code 系列）**：某些控制台会丢弃 `Ctrl+Enter` 上的 `Ctrl` 修饰键（可能退化为普通 `Enter` 或 `Ctrl+J`）。请使用 `Ctrl+I` 作为替代键——字母键 Ctrl 组合在各处都稳定。在 VS Code 系列中，请使用 **`Ctrl+L`**。

> **VS Code 系列的 `Ctrl+L`**：Grok 将其用于插话，并让扩展快捷键保持未绑定状态（用 `/plugins` 或命令面板打开插件）。如果终端配置仍将**清除**（或其他命令）映射到 `Ctrl+L`，该主机绑定可能会抢走组合键——请重新绑定或移除它，让 PTY 接收换页符（`\x0c`）。

## 全局

可从任意界面使用的操作。

| 按键 | 替代按键 | 操作 | 确认 |
|----------|---------|--------|-------------|
| `Ctrl+N` | | 创建新会话（可选在 git 工作树中） | 是（在 1000ms 内按两次） |

**VS Code 系列终端**（VS Code、Cursor、Windsurf、Zed 集成终端）：主机会捕获 `Ctrl+Q`，因此 Grok 将 **`Ctrl+D` 设为唯一退出键**（不绑定 `Ctrl+Q`）。半页向下滚动改为普通 **`Shift+D`**。轮次中途插话使用 **`Ctrl+L`**（无替代键），因为 `Ctrl+Enter` / `Ctrl+I` 无法可靠到达 PTY；通过 `/plugins` 打开扩展，而不是使用 `Ctrl+L`。

> **返回欢迎界面没有按键绑定**——请在会话中使用 `/home` 斜杠命令（别名 `/welcome`）。参见[斜杠命令](04-slash-commands.md)。

### 破坏性操作确认

确认列标为“是”的操作需要在 1000ms 内按两次。按一次按键显示确认提示，再按一次确认。这样可防止意外丢失会话。

## 快速参考卡

### 聚焦回滚区时（简单模式——默认）

```
导航：             Up/Down（上一条/下一条）  Shift+Left/Right（上一轮/下一轮）
滚动：             Ctrl+J/K（行）  PgUp/PgDn（页）  Ctrl+U/D（半页）
聚焦提示框：       Space 或任意字母键（自动聚焦并输入）
```

### 聚焦回滚区时（Vim 模式）

```
导航：             j/k（上/下）  H/L（上一轮/下一轮）  K/J（上一条/下一条回复）  g/G（顶部/底部）
滚动：             Ctrl+J/K（行）  Ctrl+U/D（半页；VSCode 中 D=Shift+D）  PgUp/PgDn（页）
折叠：             h/l（折叠/展开）  e（切换）  E（全部）
内容：             y（复制）  Y（复制命令）  Enter（全屏）
查看：             r（原始 markdown）  Ctrl+E（思考）
聚焦提示框：       i、Tab 或 Space
```

### 聚焦提示框时

```
发送：             Enter
换行：             Shift+Enter 或 Alt+Enter
多行：             Ctrl+M（切换）
粘贴：             Ctrl+V（文本、文件、macOS/Linux 截图）
选中文本：         中键或 Shift+Insert（Linux X11/XWayland PRIMARY）
粘贴图像：         Alt+V（仅 Windows——截图/“复制图像”）
全选：             Cmd+A（macOS，仅 Ghostty——参见下方说明）
选择文本：         Shift+←/→（字符） · Alt+Shift+←/→（单词） ·
                   Cmd+Shift+←/→（可视行） · Shift+Home/End（逻辑行） ·
                   Shift+↑/↓（行）
复制 / 剪切：      Cmd+C / Cmd+X（存在选区时；支持 Kitty 键盘协议的终端）
离开：             Tab（返回回滚区）
取消（运行中）：   Ctrl+C（空提示；非空草稿先清除）
清除（空闲）：     800ms 内按 Esc Esc（非空提示）
回退（空闲）：     800ms 内按 Esc Esc（空提示 + 有消息）
```

存在选区时，输入字符、按 `Enter` 或粘贴会替换选区；删除和按词删除快捷键只删除选区；方向键会把选区收拢到对应边缘（按词/按行移动会从该边缘继续）；`Esc` 或 `Tab` 会取消高亮，同时仍执行各自的常规操作。请注意，`Shift+←/→` 只有在**提示框**获得焦点时才选择文本；回滚区获得焦点时，相同快捷键会在各轮之间跳转（参见上方“导航”）。

> **Cmd+A 仅限 Ghostty。** Grok 的应用内 `Cmd+A` 处理器仅在检测到终端为 Ghostty 时连接。其他终端会在终端层吞掉 `Cmd+A`（Apple Terminal、默认 iTerm2），或在终端内应用自己的“全选”行为（Kitty、WezTerm）。在非 Ghostty 终端上，此绑定不执行任何操作，按键会落到终端的原生行为。
>
> 在 Ghostty 上，将下面这一行取消绑定添加到 `~/.config/ghostty/config`，使按键到达正在运行的 TUI：
>
> ```ini
> keybind = cmd+a=unbind
> ```
>
> Ghostty 重新加载后（它会监视配置文件），在提示框中按 `Cmd+A` 会选中提示缓冲区中的每个字符，包括粘贴的图像芯片。图像芯片始终不含路径（`[Image #N]`）；已知时的文件路径只会在悬停或光标位于芯片上/紧邻芯片后方时的图像预览覆盖层中显示。
